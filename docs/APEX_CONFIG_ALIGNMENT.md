# Apex 配置一致性与平台边界

## Steam 与 EA 的快速预设差异

| 项目 | Steam | EA |
| --- | --- | --- |
| 启动项存储 | 当前账户的 `localconfig.vdf` | 当前账户的 `user_*.ini` |
| 精简准星序列化 | `+reticle_color "2147483648 2147483648 2147483648"` | `+reticle_color 2147483648-2147483648-2147483648` |
| FOV 序列化 | `+cl_fovScale "1.7"` | `+cl_fovScale 1.7` |
| 账户标识 | `steam:<id>` | `ea:<id>` |
| 启动前检查 | Apex 与 Steam | Apex 与 EA Desktop |
| 游戏语言来源 | 账户设置；无记录时使用 appmanifest | 与安装目录匹配的 Respawn 注册表 Locale（32/64 位视图） |

画面、profile 和键位文件按机器范围处理；启动项和启动项历史按平台与账户隔离。
两端的启动项文本不同，但工具内部使用同一选项模型，写入和读取各自的格式。

不要用 Steam 的参数文本直接判断 EA 的选中状态。解析器必须同时识别空格分隔和短横线
分隔的精简准星值，保留 `+exec` 及其它未托管参数。FOV 读取也必须接受两端的引号差异。
每次重新打开都从磁盘报告重建选中状态，不能沿用旧窗口缓存。

## 必须执行的回归流程

修改任一平台的生成或解析规则后，运行：

- `tests/src/stores/game/apex/quick_preset_reopen.test.ts`
- `tests/src/stores/game/apex/quick_preset_controls.test.ts`
- `tests/src/components/game/apex/preset/apex-quick-preset-dialog.test.ts`

回归需要覆盖每个平台的每个选项、全选、写入临时文件、销毁旧状态后重新读取，以及连续
两次往返。原生文件写入和键位序列化由 Rust 测试补充；文件测试不能替代用户在游戏内
查看最终效果。

## 当前行为约定

- 分辨率只有在启动项和四个画面字段都完整匹配时才显示为已选；原生比例的两种锁轴
  结果相同，重新打开时采用锁宽。
- 空 `profile.cfg` 补齐默认设置；已有个人值和未选择的键保持不变。
  缺少绑定的 `settings.cfg` 单独补齐默认键位。
- 右键保持瞄准只匹配 `+zoom`，切换瞄准仍是 `+toggle_zoom`。重置后恢复游戏默认，
  因此两个快速预设选项都会处于未选状态。
- 最小冲刺镜头晃动写入 `sprint_view_shake_style=1`；重置恢复正常值 `0`。
- 画面预设只写本次选择的字段；读取失败、只读保护或回读不一致时保持窗口打开并
  报告失败，不发送成功通知。
- 画面文件要求 `setting.configversion` 为正的有符号 32 位整数且至少为 `10`。缺失、
  空文件和旧格式保持待生成状态，不会仅凭少量键值报告成功。

## 重置和配置生成

完整重置会在工具内根据当前安装、显示器、显存、系统内存和游戏语言生成三份配置，
保存历史后写入并回读。任何一步失败都会尝试恢复原内容和文件属性。另有可选的“由游戏
重新生成画面配置”路径；它只处理画面文件，需要用户启动并正常退出游戏，不能与完整
重置混用。

详细字段和测试契约见 [画面配置参考](APEX_VIDEO_CONFIG_FORMAT.md)。
