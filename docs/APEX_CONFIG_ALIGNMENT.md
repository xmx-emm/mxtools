# Apex 配置一致性修复

## Steam 与 EA：快速预设必须分别验证

| 差异点 | Steam | EA |
| --- | --- | --- |
| 启动项配置文件 | 当前账户的 `localconfig.vdf` | 当前账户的 `user_*.ini` |
| 精简准星参数 | `+reticle_color "2147483648 2147483648 2147483648"` | `+reticle_color 2147483648-2147483648-2147483648` |
| FOV 参数 | `+cl_fovScale "1.7"` | `+cl_fovScale 1.7` |
| 账户标识 | `steam:<id>` | `ea:<id>` |
| 应用前进程检查 | Apex 与 Steam | Apex 与 EA Desktop |

视频、profile 和键位配置在当前实现中是机器级范围；启动项和启动项历史按平台及账户隔离。

**不能拿 Steam 的参数文本直接判断 EA 的勾选状态。** 配置目录中的参数字面量采用
Steam 格式，生成器按平台序列化，解析器必须把两种格式识别为同一选项，同时保护
`+exec` 参数和非预设值。精简准星曾因“EA 参数被识别并移除，但只按 Steam
字面量恢复勾选”而在重新打开时显示未勾选；之后再次应用还可能丢掉该启动参数。

修改任一平台的生成或解析规则时，必须同时运行
`tests/src/stores/game/apex/quick_preset_reopen.test.ts`：分别断言两平台的精确输出格式，
逐项选择和全选，写入临时文件，销毁旧状态后重新读取，并连续往返两次。
该测试的启动项走实际生成器和解析器；视频、profile、键位使用模拟的原生回读报告，
原生文件写入及键位序列化另由 Rust 测试验证，不能将这些测试表述为游戏内实机验收。

## 行为修复

- 两平台还需运行 `apex_quick_preset_controls.test.ts` 与
  `apex-quick-preset-dialog.test.ts`：恢复自定义 FPS、全部画质档位及分辨率锁轴，
  等待启动器退出时禁止焦点/事件/轮询刷新覆盖选择。分辨率仅在启动项与四个视频
  字段完整匹配时勾选；原生比例下两种锁轴结果相同，重新打开采用锁宽。
- `quick_preset_profile.test.ts` 与 Rust `apex_quick_preset_profile.rs` 覆盖
  缺失、空和部分 profile：默认模板补齐只发生于空配置，已有个人值保持，
  七项选中优化允许补写缺失键。字幕即使未由游戏初始化也能明确关闭。

- 默认参数与键位修正；两个技能侧键属于游戏默认，不再标成个人偏好。
- 左方括号/分号按游戏键名写入，界面显示实际符号，未编辑行保留原文。
- 准星默认使用空字符串，与设置编辑及快照校验一致。
- DVS 使用分步整数截断，关闭时保留帧时间；补齐 1 FPS 的完整数值范围。
- 鼠标灵敏度下限为0.1，fadeDistScale下限为1。
- 删除受管 threshold 参数、旧超采样/深度羽化字段和画面迁移标志控件；
  旧启动串中的 threshold 留在自定义输入中，不静默删除用户内容。
- 视频重置改为等待游戏按硬件生成；字幕默认交给游戏语言初始化。

## 2026-09-09：重置后快速预设生成残缺画面文件

EA 实机反馈垂直同步、点光源阴影仍为默认。检查时两项在磁盘已为 `0`，但文件
只有预设写入的 27 个键，缺少 `setting.configversion` 等游戏生成字段，并且只读。
历史记录对应“重置移除视频文件 → 未启动游戏生成基础配置 → 直接应用快速预设”。
旧写入器会从空文件创建只包含选中项的 VideoConfig；旧校验只比较这些选中项，
因此能报告成功，却不能证明 Apex 接受了整份配置。

现在写入与加只读前均检查游戏的正整数配置版本，缺失、空、旧版残缺文件保持
待生成状态；即使选中值已经全部相同也不能绕过检查。前端不再从残缺文件恢复
“已应用”的画面勾选。修复入口先保留历史，再仅移除残缺的 videoconfig.txt，
由用户启动并正常退出 Apex 生成基础文件，随后再应用预设。工具不伪造版本号，
也不拿历史中的个人画质充当本次硬件默认。原生边界同时保护普通画面应用和快照导入。

**该问题不是 EA 启动项格式差异。Steam 与 EA 共用同一份画面文件，必须一起验证。**
启动项中的精简准星、FOV、账户目录差异仍按上表分别处理。

回归覆盖 `video_initialization.test.ts`、Rust `apex_video_initialization.rs` 与
`apex_video_regeneration.rs`：缺失/空/残缺配置拒写，正常文件保留游戏元数据和
未编辑值，恢复保留备份与只读属性。`quick_preset_video_native.test.ts` 将前端
选项送入真正的 Rust 读写器，在独立临时用户目录中验证两平台各 10 个画面开关、
全选及两次重新打开，共 22 项。只替代视频读写的模拟结果；游戏内菜单验收仍由
用户手动完成，不能把磁盘校验表述为游戏内已生效。

运行 `npm run test:apex-video-native` 会先构建原生测试程序，再执行以上 22 项；
Windows CI 的 Rust 任务也运行此命令。普通 `npm test` 不要求 Rust 工具链，
会跳过这组测试，因此发布前不能只依据普通前端测试宣称原生流程通过。

本次前端回归、原生文件集成、Rust 测试、lint、clippy 和构建已通过。
EA 游戏重新生成基础配置、再次应用预设后的菜单状态仍待用户实机复测。
